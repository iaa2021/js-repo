You can configure a fresh Chrome installation on each of your Linux systems to access
 your local HTTPS chat without launching Chrome with a temporary profile.

The setup has two certificates to configure:

ca-cert.pem — allows Chrome to trust your HTTPS server.

client.p12 — gives Chrome your client certificate and private key for mTLS 
authentication.

Your project directory is:

/home/iaa/Desktop/gitStore/js-repo/freeCodeCamp/node_js/express/express_web_chat/
The instructions below are for Rocky Linux, openSUSE, Ubuntu, Manjaro, EndeavourOS,
 and other Linux distributions. The system trust-store commands differ by distribution.

1. Install the certificate tools
Run the appropriate command for your distribution.

Rocky Linux / Fedora

sudo dnf install nss-tools ca-certificates

Ubuntu / Debian / Linux Mint

sudo apt install libnss3-tools ca-certificates

openSUSE

sudo zypper install mozilla-nss-tools ca-certificates

Manjaro / EndeavourOS / Arch Linux

sudo pacman -S nss ca-certificates

Chrome on Linux uses certificate stores that can vary by version and installation.
 Chromium's documentation notes that since version 146, 
 the default NSS database is ~/.local/share/pki/nssdb, 
 unless an existing ~/.pki/nssdb database is used.

2. Find your certificate files
cd /home/iaa/Desktop/gitStore/js-repo/freeCodeCamp/node_js/express/express_web_chat/certs

ls -l ca-cert.pem client.p12

Both files should exist.

3. Trust your CA at the operating-system level
Use the command for the current Linux distribution.

Rocky Linux / Fedora

sudo cp ca-cert.pem /etc/pki/ca-trust/source/anchors/localchat-ca.crt
sudo update-ca-trust

Ubuntu / Debian

sudo cp ca-cert.pem /usr/local/share/ca-certificates/localchat-ca.crt
sudo update-ca-certificates

openSUSE

sudo cp ca-cert.pem /etc/pki/trust/anchors/localchat-ca.pem
sudo update-ca-certificates

Manjaro / EndeavourOS / Arch Linux

sudo cp ca-cert.pem /etc/ca-certificates/trust-source/anchors/localchat-ca.crt
sudo update-ca-trust

Only install your own CA certificate if you trust the CA and control the corresponding
 private key. Don't install your server's private key into the system trust store.

4. Import the client certificate into Chrome
First, close all Chrome windows. Then check which NSS database your Chrome installation
 uses.

ls -ld ~/.local/share/pki/nssdb ~/.pki/nssdb 2>/dev/null

For current Chrome versions, use the following database if it exists and your 
installation uses it:

mkdir -p ~/.local/share/pki/nssdb

If your Chrome already uses ~/.pki/nssdb, keep using that database instead. Don't create
 and populate both databases blindly.

Set the database path for the next commands. For example, if you are using the newer 
default:

export NSSDB="sql:$HOME/.local/share/pki/nssdb"

Initialize it if necessary:

certutil -N -d "$NSSDB"

If it asks for a database password, set one or leave it empty if your environment
 permits.

Now import the client certificate:

pk12util -i client.p12 -d "$NSSDB"

Enter the export password you used when creating client.p12.

Import your CA into the same database as well:

certutil -A \
  -d "$NSSDB" \
  -n "LocalChat CA" \
  -t "C,," \
  -i ca-cert.pem

If the CA nickname already exists, inspect it first with certutil -L -d "$NSSDB" 
rather than importing a duplicate. The C,, trust setting identifies a trusted CA for
 issuing server certificates.

Enter the password you set when you created client.p12. The import should report
